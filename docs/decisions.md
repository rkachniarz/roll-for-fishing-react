# Roll for Fishing: decision log

Why things are the way they are. Code, tests and tools cite these by number (`D5`). Add new decisions at the end, with
the next number and the date. When one changes an earlier one, say so in both, rather than rewriting the old one.

| # | Date | Decision |
|---|---|---|
| D1 | 2026-10-28 | **Fresh start.** The React app was a learning prototype; its state handling caused most of its bugs, and the planned engine would have replaced nearly all of it. It is kept at the tag `legacy-prototype`. Its content and proven mechanics are ported, not retyped (PORTING-NOTES.md). There are no players, so no save compatibility with it. |
| D2 | 2026-10-28 | **Stack as in SuperRollies: no framework, no build step to run.** ES modules served as static files (`serve .`), libraries from a CDN through one import map in `index.html`, with exact versions pinned. esbuild only bundles the single-file artifact copy (D14). |
| D3 | 2026-10-28 | **JavaScript with `// @ts-check` and JSDoc types**, not TypeScript. Editor type checking without a compile step. The prototype's worst bugs were field-name mismatches (`active` vs `startActive`), which this catches. |
| D4 | 2026-10-28 | **Seeded randomness, one stream per consumer.** `src/rng.js` is SuperRollies' Mulberry32 + `deriveSeed(seed, label)`, unchanged. Streams so far: `cast-timing`, `fishing`, `scenery`. Nothing that affects an outcome uses `Math.random`. |
| D5 | 2026-10-28 | **The dice stay named functions:** `getRandomNumber`, `roll20(vantage)`, `roll100`, `roll6`, `roll2d6`, as written in the prototype. They are not folded into a generic `roll('2d6')`; a new die is a new function in the same style. They are bound to a stream with `diceFor(rng)`, so call sites read as before. The owner's choice. |
| D6 | 2026-10-28 | **Tests:** `node:test` for the engine and data (no dependency); Playwright for browser checks (`npm run verify`, which starts its own server). Chromium only until after the MVP, as in SuperRollies. |
| D7 | 2026-10-28 | **The engine is pure.** No DOM, no clock, no rendering in `src/engine/`: it is given `now` and inputs, and returns new state. The scene and the page only render state; nothing in the engine waits for an animation. Every roll is recorded with a `visible` flag (R5.1). |
| D8 | 2026-10-28 | **PixiJS v8 for the scene; plain DOM for the UI.** The game is 2D (water, sprites, particles). The UI (panels, inventory, dialogs) starts as plain DOM. If it gets painful, Preact + `htm` (no build step) can replace `src/ui/` alone; reviewed in Phase 5, the inventory. |
| D9 | 2026-10-28 | **Pixel art, 2D with perspective; placeholder art is generated.** The owner may draw (MS Paint, Aseprite) later. Until then: sprites as code (palette-keyed pixel grids and small drawing functions in `src/scene/sprites.js`) first, CC0 asset packs for large pieces (credited in `assets/CREDITS.md`), AI image generators for concept only. |
| D10 | 2026-10-28 | **Phone and desktop are both first-class.** A square scene, 256×256, scaled by the largest whole number of *device* pixels that fits (at devicePixelRatio 2.625, whole CSS pixels still smear). Phone in portrait: scene above the UI; wide screens: UI beside it. Input is tap-first; nothing depends on hover. |
| D11 | 2026-10-28 | **The reflex affects the catch, not the bite** (Q-5). How fast the player strikes after the splash modifies the fishing d20: fast +1, ok 0, bad −1; 3 s or more and the fish is gone. These are the early-game values; items and perks can change them later. |
| D12 | 2026-10-28 | **No accessibility options for now** (Q-7). A small project with a small audience; a no-reflex mode or similar can be reconsidered later. Touch-friendly input (D10) still applies. |
| D13 | 2026-10-28 | **One serialisable game state, saved whole after every resolved cast**, with a version number and migrations. Modifiers are always derived from the state (class, level, perks, equipped items, buffs, weather), never added and subtracted as items change: that was the prototype's main source of bugs. Refined by D44 (saves hold ids, not content) and D53 (saves hold the random streams). |
| D14 | 2026-10-28 | **Hosting:** GitHub Pages serves the repo as-is. `npm run build` makes `dist/artifact.html`, a single-file copy for publishing as a Claude artifact (publishing it is not planned: D25). |
| D15 | 2026-10-28 | **Striking before the bite pulls the line out:** the cast ends with no roll. *Provisional*, chosen for the Phase 1 trial so an early tap has a consequence; revisit after playtesting. |
| D16 | 2026-10-28 | **The reaction is timed from when the splash is on screen.** The engine schedules the bite; the first frame that shows it resets `biteAt` to that frame's time (`src/main.js`), so the player is never charged for time before they could see it. |
| D17 | 2026-10-28 | **Phase 1 timing defaults:** bite 2.5–8 s after the cast; fast under 450 ms, ok under 900 ms, bad up to 3 s. *Provisional*; the `?dev` panel offers Tight (350/700) and Lenient (600/1200) to compare on a real phone. |
| D18 | 2026-10-28 | **The cast lands where the player taps**, clamped to the open water; Space/Enter casts to a random spot. It makes casting a choice (useful later for fish schools, DEV_PLAN "Ideas for later") and is natural on a phone. |
| D19 | 2026-10-29 | **Class names are the prototype's** (Q-3): Fish Fighter, Fishing Wizard, Rogue Fisherman. Character creation asks for gender (M/F), and the Rogue becomes a Rogue Fisherwoman. Names live in the class data only, so a slicker set can replace them later. The spec's Warrior / Mage / Rogue are shorthand for the three roles. |
| D20 | 2026-10-29 | **What the stats do** (Q-4): Fishing Skill adds to the d20; Fish Find raises the bite chance; Treasure Find shifts the non-fish table towards better outcomes. Each roll uses the base stat *plus* its modifiers. The prototype rolled and saved the base Fish Find and Treasure Find but only ever added the modifiers (`PlayGameButton.jsx`); that is fixed on port. **Every number used in a calculation is a game value that modifiers can change** (items, consumables, buffs, perks, events, weather), always derived from the state (D13). |
| D21 | 2026-10-29 | **Luck is a hidden fourth stat** (Q-4): a karma meter. It plays no part in the cast; events check it, e.g. an extra option appears when Luck is positive. It is not shown to the player. |
| D22 | 2026-10-29 | **Leaving mid-cast voids the cast** (Q-6): no time passes, no roll is made. Buffs that last "the next n casts" spend a charge when the line goes out, so a voided cast still uses one up. The same holds for a cast that ends with no roll (early strike, D15; no strike in time). |
| D23 | 2026-10-29 | **No end goal: the game is a collect-a-thon** (Q-8). An accomplishments book records each fish species (smallest and largest caught) and each treasure found. Each location has a finite list of what can be found there, so its completion is a percentage. Nearly all of it starts hidden: what is missing from a list is learnt by fishing more, or by obtaining or buying knowledge (e.g. that a species or an item can be found at a location). |
| D24 | 2026-10-29 | **What fish are for** (Q-10): selling, eating (buffs) and quests, unlocked gradually as the player fishes more. The first, once the town exists: trading fish at the inn for a bowl of its perpetual stew. The bucket has no capacity for now. Refined by D50 (what the bucket holds). |
| D25 | 2026-10-29 | **No artifact publishing planned** (Q-11). What matters is testing the latest changes as they land without deploying to GitHub Pages: `npm run dev`, which also serves on the local network for a phone on the same Wi-Fi. `npm run build` stays, as it costs nothing. Updates D14. |
| D26 | 2026-10-29 | **The weather hex directions carry no meaning** (Q-12); the map was laid out so that the transitions 2d6 favours are the likely ones, so the drift is intended and is ported as-is. Edge rule: a move off the map wraps around to the far side, except across an edge marked with a line on the map, where the weather stays the same. |
| D27 | 2026-10-29 | **The Normal timing preset stays the default** (Q-15, D17); fine-tuning comes later. The `?dev` bench should expose as many game values as practical: the owner tunes by tinkering. |
| D28 | 2026-11-01 | **The perpetual stew is the early game's buff loop** (refines D24). Fish while the buff lasts, then put the catch in the stew for the next one. The buff is substantial early on. Rarer fish make it stronger, judged against the location's table, so landing a big, rare fish pays off in the next session. Each fish added makes the buff last longer. Whether it runs on time or on casts is open (Q-16). The owner leans towards time, and keeps cast-counted buffs for stronger effects. Buffs and debuffs of both kinds will exist either way. Answered: time (D37). |
| D29 | 2026-11-01 | **UI: when in doubt, copy World of Warcraft.** Where WoW's behaviour isn't known for sure, ask the owner rather than assume. First case: the buff and debuff display (R12.3–R12.5), in WoW's place at the top right of the game area. The owner's note says "on hover", and D10 rules out anything that only works by hover, so a tap opens the description on touch screens, as with inventory tooltips (R8.7). |
| D30 | 2026-11-01 | **The Alchemist visits town as a recurring event.** They sell buffing potions and buy alchemical ingredients, from vials up to rare magical goo. All ingredients are fished up as junk. This gives a use to a class of junk that the scrap dealer undervalues. |
| D31 | 2026-11-01 | **Buff bar details** (D29). The timer rounds to the *nearest* minute, a deliberate departure from WoW, which rounds up. As in WoW, the player can cancel a buff early: right-click on desktop, long-press on touch. Debuffs can't be cancelled. |
| D32 | 2026-11-01 | **Timed buffs and debuffs count down only while the game is open** (Q-17), so leaving the game costs nothing (R1.1). This is real time, separate from game time: game time still moves only with the player's actions (R11.4). |
| D33 | 2026-11-01 | **Fish schools and other surface features are now a planned mechanic**, moved up from "Ideas for later". Schools of fish, curious spots and disturbances show up on the water's surface. If the bobber lands directly in one, the odds of what comes up change. This builds on the cast landing where the player aims (D18, D34). How the features behave: D40. |
| D34 | 2026-11-01 | **The bobber lands near the aim, not exactly on it.** Refines D18. The rod's accuracy (D35) sets how far from the aimed point the bobber may land, so landing in a school (D33) takes both aim and gear. The scatter affects outcomes, so it draws from its own seeded stream (D4). |
| D35 | 2026-11-01 | **Fishing rods have stats, and they feed different stats from the ones the character feeds.** The player starts with a stick with some string tied to it. Better rods come from fished-up treasure, events and the like. All stats are the player's: each is a total of whatever contributes to it (character, items, buffs), as in D20. *Provisional*, a loose idea from the owner: the character mostly feeds the stats behind the rolls (Fishing Skill, Fish Find, Treasure Find, D20), and the rod mostly feeds the stats behind the cast: accuracy (D34), the reaction window for the strike bonus (R2.3), and how long fish take to bite (R2.2). Fish Find still sets whether a fish bites; the rod sets how soon. Rods must have downsides (R8.5): D38. |
| D36 | 2026-11-01 | **Bait is an optional consumable attached to the rod.** The player can always fish without bait. The smallest fish can be used as bait to catch predators. How bait is used up and what it does: D39; which fish can be bait: D41. |
| D37 | 2026-11-01 | **The stew buff runs on time** (Q-16, refines D28), counting down as D32 describes. Each fish added is worth some extra buff time; how much per fish, and the buff's numbers, are left for balancing. |
| D38 | 2026-11-01 | **Rods follow R8.5: every better rod has a downside** (Q-18), a deliberate departure from WoW, whose poles simply get better (D29). Downsides breed creativity and let the upsides be stronger. Examples from the owner: a more accurate rod is slower, so fish take longer to bite; a rod that widens the reaction window for the strike bonus makes the bobber drift, as if too lively to stay still. |
| D39 | 2026-11-01 | **What bait does, and how it is used up** (Q-19, refines D36). Bait raises the chance that a cast brings up a fish rather than junk or treasure (R3.1), and some baits also favour particular fish: some love balls of bread pulp, others meat, others live bait (small fish, D41). Bait is used up when a fish is caught, with a chance that it is saved. The message says which: "[bait] was recovered" or "[fish] has eaten [bait]". Items can raise the recovery chance. The recovery roll affects outcomes, so it draws from its own seeded stream (D4). Whether bait is lost when a fish bites and gets away: D61. |
| D40 | 2026-11-01 | **How surface features behave** (Q-20, refines D33). The earlier idea stands: ripple patches drift around the scene and thin out as they are fished, and a school favours a species or raises the bite rate. Sometimes a single, specific big fish shows just under the surface. Curious spots work like schools but for treasure or specific junk. Disturbances start magical events (R10): anything from a fish that can talk, a lady of the lake or a merman fishing for people, to a portal to hell that pulls the player in and changes the location (R11). Whether features are always visible: D62. |
| D41 | 2026-11-01 | **Any fish landed in the Tiny size band can be used as bait** (Q-21, refines D36), for now. It is a consolation prize: the smallest possible catch can still go on the hook to catch a big predator. It is caught like any other fish first (accomplishments book, bucket). |
| D42 | 2026-11-01 | **Game content is data, not code.** Locations, fish, items of every kind and events live in `content/`, one file per entity (`content/fish/pike.json`), so adding one is adding a file. JSON, with a JSON Schema per kind, so VS Code checks and completes it. A location lists what can be found there (fish, junk, treasure, events, with weights), and may include shared lists from `content/tables/`. Nothing is marked exclusive: whatever only one location lists is exclusive to it, which also gives the completion lists (R4.4). Each entity may name an icon; without one, or until the sprite exists, its kind's default icon is used. Anything the existing fields and effect words can express needs no code change; a new mechanic or a new effect word is code work first. Refined by D56 (more kinds, one shared effect vocabulary). |
| D43 | 2026-11-01 | **One command builds the content: `npm run content`.** It checks everything (ids unique and spelled right, references resolve, weights valid, a downside on every beneficial item, R8.5; events parse), converts the event files, and writes one bundle the game loads. It also reports what still has no art and writes a read-only overview page with sortable tables of all content, for balancing. `npm test` runs the same checks. The bundle is committed and a test fails if it is out of date, so the game still runs straight from a checkout. Relaxes D2 for content only: code still runs with no build step. |
| D44 | 2026-11-01 | **Saves outlive content changes** (refines D13). A save holds only the player's own state and ids, never a copy of content, which is loaded fresh at every start. New content appears in existing saves and changed numbers apply at once. Ids are permanent: never renamed, never deleted. To remove something, mark it `"retired": true`; old saves still resolve it and tables skip it. The aim is one save forever, once the game has players. New content changes what a given `?seed` replays; that only matters for development. |
| D45 | 2026-11-01 | **Events are written as text**, one Markdown-like file each: front matter for the id and title, a section per slide, a bullet per choice with an arrow to the next slide, and indented lines for requirements and effects (`needs:`, `gain:`, `lose:` …). Those words are a fixed vocabulary in code; a new word is code work (D42). Where an event can happen and how likely it is lives in the location file, so the event file is only the story. The exact format and the full list of words are worked out with the frog encounter in Phase 7. The effects themselves are shared with items and come earlier: D56. |
| D46 | 2026-11-01 | **Player-facing text goes through a string table from the start.** Text is written in English in the content files, where it belongs; `npm run content` collects it into a table keyed by id and field (`fish.pike.name`), and the game reads text through one lookup. Code's own UI strings use the same lookup. A translation would then be one more file per language. Translation is unlikely, but this costs next to nothing now and a lot later. |
| D47 | 2026-11-01 | **A content editor app comes later**, once the content kinds have settled. Events are text and VS Code checks the JSON against the schemas, so until then the editor has little to add; the overview page (D43) covers looking at content. When it comes: a page served by `npm run dev` with forms generated from the schemas, saving straight into `content/`. |
| D48 | 2026-11-01 | **Items are hand-made, not rolled** (Q-24). Every item is defined once and is the same wherever it turns up; no Diablo-style random affixes. An effect may still roll when it applies, such as +1d4 to a roll. A die named in content maps onto one of the named dice functions (D5), so a new die is still a new function; the roll draws from a seeded stream (D4) and is recorded like any other (R5.1). |
| D49 | 2026-11-01 | **Rarity uses WoW's tiers and colours** (Q-25): Poor (grey), Common (white), Uncommon (green), Rare (blue), Epic (purple), Legendary (orange). A fish's rarity is its species' rarity, raised by its size band: a roach is Common but a huge roach is Epic; a pike is Rare, and Epic when huge. How many tiers each size band adds is set in data. Legendary fish are named and unique. |
| D50 | 2026-11-01 | **The bucket holds fish, the bags hold everything else** (Q-26, refines D24). Every caught fish goes into the bucket until the player does something with it. Fish keep their species and size, and stack only with an identical twin. Whether the bucket gets a capacity, to send the player to town, was open (Q-31): yes, D57. The player should never feel buried in junk. |
| D51 | 2026-11-01 | **Quests are events linked by flags** (Q-27). Objectives exist but are mostly hidden: conditions on what the game already counts, such as the accomplishments book. An event can also move the player to a location they can't leave until they meet an objective, such as the portal to hell; the event explains this. So events need triggers on counters and flags, and locations can be closed to the location switcher. |
| D52 | 2026-11-01 | **A location's completion can drop when content is added** (Q-28), and that is welcome: there is something new to find. Retired content (D44) stays in the book for whoever found it but no longer counts towards completion. |
| D53 | 2026-11-01 | **The save holds the position of every random stream** (Q-29), not only the seed. Each Mulberry32 stream is one 32-bit number, so this costs nothing. A reload continues the same sequence, so there are no fresh dice to be had by reloading, whatever rolls early in future. |
| D54 | 2026-11-01 | **No tutorial for now** (Q-30). The player learns from dialogue and events, as in WoW. To revisit once friends playtest. |
| D55 | 2026-11-01 | **The game can be installed and played offline, late in development** (Q-32): a web app manifest and a service worker. Until the owner calls the game ready it has no players, so the risk of Safari clearing an uninstalled site's storage after a week away only matters then. |
| D56 | 2026-11-01 | **The effect vocabulary comes in Phase 2, and content covers more kinds** (refines D42, D45). | D61 | 2026-11-01 | **A fish that gets away has a small chance to take the bait** (Q-22, refines D39): 5% for now, a game value like any other (R6.6). It draws from the same stream as bait recovery (D4), and the message says so ("[fish] got away with [bait]"). |
| D62 | 2026-11-01 | **Surface features are never hidden** (Q-23, refines D40). | D63 | 2026-11-01 | **Calls for Phase 2**, agreed with the owner. | D64 | 2026-11-01 | **Every cast ends in a splash, and missing it costs time, not a recast** (Q-35). Junk and treasure "bite" too, as in WoW. Only fish fight back: the d20 is rolled against fish, and anything else is landed by any strike in time. A "nothing" result is reported in the log as an empty hook. Unlike WoW, where a missed splash means the line expires, a missed splash ends that cast as resolved (the catch is lost, a fish joins the escaped pool, bait may go, D61, and time passes); then nothing happens to the bobber for 5 seconds, after which the line counts as freshly cast: a new cast, with new dice, spending charges as any cast does (R1.5). A tap during those 5 seconds pulls the line out (D15). A second miss in a row reels the line in, so the game doesn't keep fishing for a player who has walked away (spending buff charges, bait and game time). The 5 seconds and the limit are game values. |

| D72 | 2026-11-02 | **How the content pipeline landed** (2.14, D42–D46). The game loads content from a generated ES module, `src/generated/content.js`, rather than a JSON file: it imports the same way in the browser, in `node:test` and in the artifact build. The R8.5 check is a warning until 5.3 gives the prototype's treasure real downsides; it flags the Mega Mass Fish Chum. Base rarities are first guesses for the owner to adjust: Carp and Roach Common; Bass, Trout and Cod Uncommon; Pike and Sturgeon Rare; all junk Poor; treasure Uncommon to Epic. |

| D74 | 2026-11-02 | **Calls made while building the cast pipeline** (Phase 2), for the owner to overrule. (1) When the line goes out, the page saves a *checkpoint*: the state with that cast's buff charges spent and nothing else. A reload mid-cast therefore loses the charge (D22) and replays the same dice (D53, D63); the two rules looked at odds and aren't. (2) A buff counts for the cast whose line spends its last charge.
