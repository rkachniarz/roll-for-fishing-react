# Roll for Fishing: notes for Claude

A pixel-art fishing game for phone and desktop: cast, watch the bobber, strike when it splashes, and roll a d20 to land
the catch. PixiJS for the scene, plain DOM for the UI, no framework, no build step to run it. See README.md for the
file map.

## Development plan

**Read `DEV_PLAN.md` before starting work.** It holds the open questions and the remaining phases, with tickboxes. Tick
tasks off as they land. It has two tracks (D105): development, and creative work (art, writing, sound, `CR-n`).
**Creative work never blocks development:** when a task needs art or text that isn't there, build it with a
placeholder (squares and triangles, a plain sentence, a stand-in rule in REVIEW.md) and list the placeholder under the
`CR-n` task that will replace it. The rest is in `docs/`, read when a citation calls for it, since code comments cite all of these
by number:

- `docs/decisions.md`: the decision log, `D1` onwards. Record new decisions there rather than silently changing
  requirements.
- `docs/spec.md`: the vision, requirements (`R1.1`–`R21.1`) and catalogues (`§C.1`–`§C.6`).
- `docs/history.md`: finished phases, task by task, with what was measured.
- `docs/events.md`: how to write an event, and every word of the format (D84).
- `docs/art.md`: how the art is made with the owner (D90): style rules, sizes, trials, drawings in MS Paint. Read it
  before changing any art.
- `docs/placeholders.md`: every placeholder in the content, generated by `npm run content` (D124). The owner loves
  placeholders: make them freely for any content, and **mark every one** (`"placeholder"` in a content file,
  `placeholder: true` in an event, `PLACEHOLDER_UI` in `src/strings.js`), so they can be told apart.
- `docs/REVIEW.md`: guesses and calls Claude made that the owner hasn't checked yet. **Add to it** whenever you pick a
  number, write content, or decide something the owner didn't (D76); the owner deletes items once settled.
- `docs/ideas.md`: the owner's loose ideas for events, people and the story, not requirements yet. Read it before
  writing events or content; the engine work they need is in DEV_PLAN.md.
- `docs/PORTING-NOTES.md`: what to port from the React prototype (tag `legacy-prototype`; read old files with
  `git show legacy-prototype:src/Data/weather.js`) and the lessons it taught.
- `docs/town-questions.md`, `docs/brainstorm-2026-11-14.md`, `docs/ideas/items.md`: dated records of questions and
  ideas, not requirements.

Pushing `master` publishes the game to GitHub Pages once `npm test` passes (D91, D133):
https://rkachniarz.github.io/roll-for-fishing-react/ (and `art.html`). Push only when the owner asks.

A phase ends with `npm test` and `npm run verify` passing, then `npm run build` (`npm run check` does all three), then a docs refresh: DEV_PLAN.md
(ticks, "Where things stand"), history.md, this file, README.md, and `npm run prompts`.

**Prompt count:** `npm run prompts` records how many prompts the owner has given per session in `docs/prompts.json`
(counts and dates, never the text), so the number survives Claude Code deleting old transcripts. Run it at the end of
every phase, and whenever the owner asks how many prompts it has taken; it never drops a session already recorded.

**UI: when in doubt, copy World of Warcraft (D29).** If you aren't sure how WoW does something, ask the owner instead
of guessing.

**Strings the owner changes:** when text in `src/strings.js` or `content/` changes without Claude changing it, the
owner did it on purpose (D85). Keep it; don't put Claude's wording back.

## Commands

```bash
npm install
npm run dev     # http://localhost:8001 - must be served, ES modules don't load over file://
npm run content # check content/ and regenerate src/generated/content.js (run after editing content)
npm test        # unit tests (node:test): rng, dice, content, weather, time, fish, the game engine
npm run verify  # browser checks in headless Chromium; starts its own server on :8123
npm run verify strike   # only the checks whose label contains "strike"
npm run build   # -> dist/artifact.html, the single-file copy for claude.ai
npm run check   # test, verify, build in turn, stopping at the first failure
npm run sprite export bobber   # a sprite as art/bobber.png to draw on; `import <file> [keys=icons] [bg=ffffff]` reads one back
npm run photo-icon <photo> name=icon-fish-<id>   # a first-draft 32×32 icon from a photo; follow the photo-to-icon skill
npm run cutout <photo> [flip=Name]   # cut the subject out of a busy photo, onto magenta (first: npm run cutout setup)
npm run commons search <slug> "<query>"   # Wikimedia Commons pictures on a contact sheet; then commons fetch <slug> <n> name=<Name>
npm run sim [casts=500 games=20 class=rogue-fisher strike=250..900 perks=first|passive|active]   # balance: seeded games per class (9.1)
npm run planks [pine|oak]   # the light theme's tabletop tile, from docs/design/refs/, into styles.css (D143)
npm run obsidian            # the dark theme's obsidian tile, drawn as code, into styles.css (D145)
npm run map                 # the map's paper and outline, from docs/design/map/, into src/generated/map-paper.js (D161)
npm run prompts # record the owner's prompts per session in docs/prompts.json, and print the total
# http://localhost:8001/art.html   the art sheet: trials, fish that swim, the painted spots by season, every sprite and icon enlarged;
#   each section folds and builds when opened; #seed=N, #open=all (a # not a ?: serve redirects art.html and drops a ?)
# http://localhost:8001/?ph          placeholder text marked with a ° (D124)
# http://localhost:8001/?dev       dev bench; ?seed=N seeds a new game (a save wins); ?wait=MS fixes the bite delay
# http://localhost:8001/editor.html   the content editor (7.5): forms from the schemas, saving into content/ (Chrome, Edge)
```

## Things that look arbitrary but are not

- **`src/generated/content.js` is generated and committed (D43, D72).** Edit `content/`, then `npm run content`; a test
  fails if the two disagree. Text in it is keys (`fish.pike.name`); read it with `t()` from `src/strings.js` (D46).
- **Content ids are permanent (D44).** Never rename or delete one; set `"retired": true` instead.
- **`src/engine/game.js` (`castLine`) rolls everything on the line when it goes out (D63),** hidden, and returns a
  `checkpoint` to save while the cast is in progress: buff charges spent, nothing else (D74). Saving the full state
  mid-cast would let a reload reroll the line.
- **The save holds every random stream's position (D53),** not just the seed. Take dice with `diceFrom(state)` and
  store `commit()` in the next state; never create a stream from the seed mid-game.

- **`src/dice.js`: the dice are separate named functions on purpose (D5).** `roll20`, `roll2d6`, `roll100`… Don't
  merge them into a generic `roll('NdM')`. A new die is a new function in the same style.
- **Nothing that affects an outcome may use `Math.random` (D4).** Draw from a stream: `deriveSeed(seed, 'label')`, one
  label per consumer, so extra draws in one system never shift another. Cosmetic randomness in the scene uses the
  `scenery` stream for the same reason (it keeps screenshots reproducible).
- **`src/engine/` takes `now` as an argument and never reads a clock (D7).** That's what lets the tests play a whole cast
  in a few lines.
- **`src/engine/cast.js` (`tickCast`) checks for a late strike straight after the bite starts,** in the same tick. A long
  gap between ticks (a background tab, a late strike) would otherwise skip past a bite that has already run out.
- **`src/main.js`: `biteAt` is reset to the frame that first shows the splash (D16).** The engine's scheduled time can
  be most of a frame earlier; the player is timed from what they can see.
- **`src/scene/scene.js` (`scene.fit`): the scale is a whole number of *device* pixels, not CSS pixels (D10).** At
  devicePixelRatio 2.625 a whole CSS multiple still smears. The canvas backing store is 256 tall and 256-320 wide; the
  browser scales it with `image-rendering: pixelated`.
- **The scene is wider than the play area (D93).** Strips of scenery either side fill the screen's width; everything the
  engine places, the cast and the bobber live in the `play` container in 256×256 coordinates, moved right past the
  left strip. Convert pointer positions with `scene.toScene` / `scene.toClient`, never by dividing by 256.
- **Sprites are never scaled at runtime (R7.3).** Depth uses separate sprites per depth band (`BOBBER` / `BOBBER_FAR`).
  Positions are rounded every frame.
- **`src/scene/sprites.js` (`paintBackdrop`): the dithered rows between water bands** stop the band edges reading as
  horizon lines.
- **`src/main.js` saves the `checkpoint` while a cast is in progress, the full state otherwise.** The dev bench
  only changes the state between casts for the same reason. Its game value overrides and `?wait` are `extra`
  sources passed to the engine, never saved.
- **`styles.css` holds both themes' patterns as data URLs** (`planks:start`/`planks:end`, `obsidian:start`/`obsidian:end`),
  written by `npm run planks` and `npm run obsidian` (D143, D145); don't edit them by hand. Background: plain
  turns them off (D144, `data-background`, read in `<head>`). It is on `body::before`, so its pixelated look isn't inherited.
  While `body[data-phase=loading]`, everything but the background is hidden.
- **`index.html` has a small script in `<head>`** that reads the theme, the background (D144) and the font
  (D132) from the settings key before the page draws, so a light page doesn't flash dark. It duplicates
  `src/settings.js`'s key on purpose (D81).
- **Event pictures are icons too, 64×64 (D142):** `event/<name>`, the scroll by default (`eventIcon`), in a round
  portrait on the event dialog; `paintIcon` sizes its canvas to the grid. Draw them inside the circle.
- **Icons are 32×32 (D98), but the first grids in `src/scene/icons.js` are 16 wide:** those above the
  `DRAWN_AT_16` line were drawn before D98, and `paintIcon` doubles them. New icons go after that line, at 32.
  An icon can keep its own colours in `OWN_KEYS`; always draw and export with `iconKeys(name)`, never `KEYS` alone.
- **Rarity colours are CSS variables (`--rarity-*`),** not the hex values in `src/scene/icons.js`: each theme has its
  own, so use `rarityColour()` from `src/ui/links.js` for anything on the page (D81).
- **`art.html` repeats `index.html`'s import map;** a test checks the two agree. It's the art sheet, not part of the
  game, and the build leaves it out.
- **`createScene` takes a `SceneLook`** only for the art sheet's trials (`src/art-trials.js`). The game passes none;
  a knob goes once its trial is settled.
- **`styles.css`: `font-variant-ligatures: none`.** Pixelify Sans, the Pixel font setting (D132), draws its "fi"
  ligature as an "A".
- **Equipped items are not in the bags (D83).** A slot holds a stack (`{ id, count }`); only the bait slot ever holds
  more than one, and bait is used up from it. Move items with `src/engine/equipment.js`, never by editing
  `equipped` and `bags` by hand.
- **The bag pane sits over the log, not over the scene (D83),** so it can be open with the character pane on a phone.
- **The save keeps only the perks taken, level -> id (D96).** What a character is owed is worked out from its level
  (`src/engine/perks.js`), and only the lowest owed level can be chosen, so a later level's random offer never
  depends on a choice not yet made. Universal offers come from a stream keyed by the level, never stored.
- **Cooldowns and an ability's "next cast" count attempts, not casts (D96):** a strike in time on a splash, the
  empty hook included. Ability buffs last `attempts`; one used mid-cast is `pending` and isn't spent by that cast,
  and its cooldown is `pending` too, counting from the next line out (D113).
  Lit abilities (`state.lit`) go dark when the next line goes out (`castLine`).
- **`src/ui/drag.js` reads `data-drag` / `data-drop` (`bag:3`, `bag:end`, `bag:pane`, `equip:rod`) off the elements;**
  `main.js` decides what a drop and the quick move do (`onDrop`, `onUse` = `quickMove`). Only a mouse drags (D163);
  a right-click, or a long press on touch, is the quick move: equip, drink, or back to the bags. The long press is a
  timer and Android's `contextmenu` both, whichever comes first, once per press (iOS may send no `contextmenu`), and
  the click after it is swallowed. On a fish in the bucket a long press opens the fish's options menu instead (R21.1).
- **A tap or left click on a paper-doll slot opens its list (D164),** as WoW's flyout: the slot is kept in
  `flyoutKey` in `src/main.js` and the list redrawn with the pane, so it never shows stale bags. It relies on the
  swallowed click above: a long press or right-click on a slot must fire no click, or it would open the list too.
  The hint at the foot of a bag item's tooltip goes by `usingTouch()` in `src/ui/tooltip.js`.
- **Events are `.md`, not JSON (D45, D84).** `tools/event-text.mjs` reads them and owns the vocabulary;
  `docs/events.md` is the author's guide, so a new word goes in both. The engine imports only typedefs from it.
  Event text is a list of parts, each its own string key (D88); a new placeholder goes in `PLACEHOLDERS` there and
  in `src/ui/event-words.js`, and a test checks the two agree.
- **The event dialog ignores clicks for 400 ms after it opens,** so the Space press or tap that ended the cast can't
  pick a choice.
- **`src/main.js`: the roll's log lines, the catch's flight and any dialog wait for the dice (D99),** and the next
  `apply` ends the show at once (`finishDice`). `body[data-dice]` is set while they're out; `tools/verify.mjs` waits
  for it to go before reading the log.
- **The spots hold the fish, not the locations (D101).** A location's `fish` list is empty; each spot's weights come
  from the owner's encounter ranks. A fish's `prefers` multiply its weight (`src/engine/tables.js`); the weather words
  are in `content/rules/fish-preferences.json`, and fog and snow are `tags` on the weather cells. Schools and big
  fish are listed per spot too (D102), and so are rift fish, `rift: true`, in each spot's `rift` table (D104).
- **Perks that change what comes up (D106) work through game values** (`riftChance`, `greedyChance`,
  `treasureChoice`, `junkToTreasure`), read in `rollLine` / `rollLoot` in `src/engine/game.js`, and every item that
  comes to the player goes through `receive()` there: Fence's choice of two waits in `state.pendingTreasure`, and
  Polish's buff is spent by the junk it turned.
- **Class fish (`src/engine/champions.js`, D114) live in `state.champions`, per spot,** not in `state.features`:
  travel clears the features but never them. Their effects reach a cast through `valuesFor` (`championSources`), so
  only at their own spot, and they draw only from the `champions` stream, so a game without them draws nothing more.
  A fish's `champion` mark stays in the bucket and comes off when it's let go.
- **Painted spots (D115-D118, D158):** a spot's `look.painting` names a painting (`"pond"`: still water, `src/scene/pond.js`;
  `"reedy"`: the reedy shore, `src/scene/reedy.js`; `"swamp"`: `src/scene/swamp.js`, painted in `swamp-pixels.js`), and `src/scene/scene.js` (`PAINTINGS`) hides its own water,
  waves, cloud shadows and reeds there for the painting's back and front layers, repainted when the spot or the
  painting's own season changes (the pond has two seasons, the reedy shore and the swamp four). A painting is seen from eye level, so each such spot has its own open water (`water`).
  The swamp's comes from its layout (`SWAMP_LAYOUT`, 32 columns further right): change the two together.
  A painting can also have a picture under the water (`UNDER` in `src/scene/views.js`, D159), shown for Look
  Underwater and the dive; `body[data-under]` names the one showing, for `tools/verify.mjs`.
- **The sky is its own layer (D169, `src/scene/sky-layer.js`):** a painting that shows sky paints nothing above its
  `horizon` (row 110 for the still water and the reedy shore) and gives `horizon`, `skyline` (the top of its land
  per column, which hides the sun and its glitter), `waterLayer` (a container in `back` just over the water, where
  the glitter hangs) and `isWater`. The sun's and the moon's height is 4 px a degree up from the horizon; across,
  the view's 60° over 256 px carried on over the strips. The still water's water still mirrors its photo's sky
  (`paintMirrorSky`), never shown itself; with `mirrorSky` the layer lays the live sky over it faintly (D170). Take
  the glitter and the mirror off a painting (`attach(null)`) before destroying it: they hang on the painting's water.
  The scene needs `World.time` and `World.fullMoonAt` for the sun and the moon.
- **The clouds (D170) come from `content/rules/sky.json`, drawn by `src/scene/clouds.js`:** `skySpec` picks fog
  first (a weather tagged `fog` hides the sky), then a description that names a sky (keyed by its string key, so
  a description that mentions cloud or sky needs a case: a test checks), then rain cloud, then the season's table.
  It reads the weather's `description` and `cell` as the engine keeps them; the art sheet passes `tags` instead.
  A sky-wide pattern goes under the sun and the moon (they show through as much as `veil` says), single clouds over
  them. Cloud grids depend only on the scenery stream and are cached per session; pattern ids are named in
  `sky.json`, so never rename one without changing both. Black (clouds 5) brings `dusk` through the night tint
  (`cloudDusk` in `src/scene/sky.js`).
- **`styles.css`: `--text` is the text colour; `--type` is the text size factor** (`--ui`, 1.25 on a wide screen,
  D121, times the font's own factor: Alegreya Sans is set at 1.05, D132). Every `font-size` is `calc(Npx * var(--type))`. `fit` in
  `src/main.js` sets `--ui`, `--hud`, `--button`, `--slot`, `--slot-icon` and `--tip-icon`; the icons are whole device
  pixels (D119).
- **Tooltips go through `bindTip` (D119):** hover with a mouse, a tap on touch. A bare `showTip` toggles and has no
  hover.
- **The town is a location with `town: true` (R17.1, D123),** `hidden` until the nightfall event opens it (D130): no casting (`castLine` refuses), no cold, no Release, and the scene
  shows `src/scene/views.js` in the water's place. Its places are spots; arriving at one opens its event, WoW's
  gossip window, and a tap on the place the player is at opens it again. An event's `go:` arrives once the event
  closes. Unit tests, the sim and `tools/verify.mjs` take an event's *last* choice, since a first choice may be a trip
  to town; a new game opens with the welcome, which the checks pass with `passWelcome`.
- **The cold and night fishing are never stored (D126):** `valuesFor` works out the values, then the cold from their
  warmth, then the values again with it (`src/engine/conditions.js`). A test that reads a raw value can meet a chilly
  morning; compare against the same moment instead.
- **A non-fish rolls twice (D125):** treasure, then stuff against `stuffThreshold` with Stuff Find, then junk. White
  things live in the `stuff` lists, never in junk's.
- **Taste is learned by eating (D138):** `state.tasted` holds the species eaten, raw or in a bowl. A fish's tooltip
  can't see the game, so `src/main.js` tells `src/ui/links.js` when to show a taste (`showTasteWhen`); the journal
  reads the state itself. The `taste` stream is drawn only for a fish with a parasite risk, and for a bowl with more
  than one kind to pick from.
- **A spot's pool (`state.escaped`) is what lives there (D139, D156, D157),** and it lives whether the player is
  there or not: `stepTime` gives every stocked pool its turn with each new part of the day (`stepPools` in
  `src/engine/pool.js`: fish leave, predators eat, others arrive), and each cast drifts the fish where the player is
  (`driftPool`). `stepTime` and `passTime` take the whole dice record for that. Stocking is still lazy (`tendPool`,
  from `castLine`, the dive, the wizard's look, and `render` in `src/main.js`); call it before taking dice, as it
  commits its own. No bait and none of the player's values count for who lives there (D153). Put a met fish back
  with `joinPool`, never by pushing onto the list. A test that counts a pool must leave out the `wild` fish.
- **The fish that bites is mostly a pool fish (D157),** taken out of the pool onto the line (`take` in `rollLine`)
  and put back if it gets away. On the line it carries the cast's difficulty and XP values and `plain`, what it
  goes back as; strip `plain` and its pool fields (`n`, `x`, `y`, `since`, `stays`, `of`) before it reaches the
  bucket, as `catchFish` does.
- **A big fish is a pool fish marked `of` its feature's `born` (D156),** brought in by `bringFeature` and taken out
  by `partFish` (`src/engine/features.js`) when the feature goes or the player travels. The pool's turns, its room
  and a random bite leave it alone. Schools are not features any more: three of a shoaling kind in a pool are one
  (`shoalsIn`, D157). Class fish are not in the pool (`state.champions`).
- **Which pool fish show as shadows, and where, is the engine's (`shadowsOf`, D156),** worked out from the state
  with a hash and no dice, so a cast can land on one (`aimedAt`). The page only draws that list, keyed by each
  fish's number `n`, so one that moves swims there.
- **A fish's weight is worked out, never stored (D146):** `fishWeight` from its species' `lengthWeight` and its own
  `condition`, rolled from the `condition` stream wherever a fish is rolled. Two fish of a different condition
  don't stack (`sameFish`).
- **The water has a temperature (`state.water`, D149),** stepped with the time in `stepTime`; who spawns is worked
  out from it (`src/engine/spawning.js`) and reaches the tables through the moment (`momentOf`), like the
  preferences. Whether it is warming is the water against its own slow average (`state.waterSlow`, D153), never
  the air against the water: that flips with every change of weather. Plants at a spot (D150) reach them the same way (`hasPlants` in `src/engine/tables.js`).
- **The action bar takes statuses that aren't perks (D148):** the adjustable line's depth button brings its own
  `label` and `tip`; `useFromBar` sends `line-depth` to its window.
- **The stew cooks (D165):** a fish in the pot carries `stewedAt`, the game minute it went in; a bowl takes only those
  `cookingFor` says are done. Strip `stewedAt` when a fish leaves the pot (`takeFromStew`). Sleeping at the inn or
  in the room sets the flag `inn-morning` and goes to the inn, where the event `inn-morning` opens instead of
  `the-inn`; each of its choices clears the flag.
- **The aquarium's meals happen on coming into the room (D152),** in `travel`, from the `tank` stream; never while
  the player watches. An event's `go:` into the room runs them too (`src/engine/events.js`), as `travel` does.
- **A landed fish can still fight (D141):** `strikeLine` may return a cast in phase `fight` instead of `done`; the
  next strike, at or after `fightAt`, answers it. Anything that plays a cast (test helpers, the sim) must strike
  again then, and the page treats `fight` as a line still out. The scene is given it as `waiting`, then `bite`.
- **Time moves in half-hour steps through `stepTime` (`src/engine/passage.js`)**, for a cast and for `wait:` and
  `sleep:`; buffs with `until` end there. Buffs can last casts, attempts, real ms or game minutes.
- **Swimming fish are drawn as code (D131):** `src/scene/fish-art.js` paints each from its shape in
  `src/scene/fish-shapes.js` (a preset for its kind of body, its own fins, tail and pattern) and the colours of its
  icon, read off the icon turned level. A new fish needs a shape there (a test checks). Side on in the tank and the
  dive; from the bank, darkened, under the surface. Made once per species and cached: new sprites, not runtime
  scaling (R7.3); facing right is a mirror. A fish with no shape falls back to its icon turned level (D129).
- **`src/main.js`: a tap within 500 ms of the last action is ignored after a cast ends,** so a double tap on the splash
  strikes once instead of striking and instantly recasting.
- **Fish Find by depth (D137, D148) is one d100, checked once per depth's bonus** (`rollLine` in `src/engine/game.js`).
  With no bonus the checks are one and nothing more is drawn (a test checks). `state.lineDepth` stays set when the
  line comes off; it counts only through `lineAdjustable` and `depthSources`.
- **The moon counts for the fish but is never stored (D168):** `moonNow(state)` (`src/engine/moon.js`) works out its
  words (into the moment, for `prefers.moon`), the moonlight and the anglers' period (a buff from `conditionBuffs`)
  from the clock and `state.fullMoonAt`. A state without `fullMoonAt` (a fixture built by hand) has no moon at all;
  a test that compares values or counts shadows at night can drop it to leave the moon out.
- **Luck is read through `luckOf(state)` (`src/engine/events.js`),** which adds the marimo's +1 (D150). Reading
  `state.character.luck` skips it.
- **Tend the pool before taking dice:** call `tendPool` or `tended` (`src/engine/pool.js`) before `diceFrom`, or
  the commit writes the old stream positions back over the pool's draws.
- **A new random stream means a new `SAVE_VERSION` and a migration that derives it** (`STREAMS` in
  `src/engine/state.js`), or an old save has no position for it.
- **The sun and moon are worked out from the clock (D167, `src/engine/sky.js`);** the one thing stored is
  `state.fullMoonAt`, the first full moon, rolled once at a new game from the stream `moon`. Like `start`, that stream
  is drawn once and isn't in `STREAMS`. The sun's hours are stretched to cross the horizon at exactly `SUN`'s times.
- **Conservation (D140) counts in the flag `endangered-released`** through `conserve` (`src/engine/barter.js`), called
  from both release paths, `letGo` and `releaseFish`. A test wants two endangered kinds per spot (one in the tower's
  pool), so adding a fish to a spot or marking one endangered can fail it.
- **A new fish needs `swims` (D136, a test checks) as well as a shape.** The schema requires only id, name, size,
  difficulty and rarity; code falls back quietly when `swim`, `fights`, `taste` or `lengthWeight` is missing.
- **Shoaling, swim styles and hiding (D147, D151, D152) are looks only,** in `createShoal` in `src/scene/swim.js`, on
  scenery randomness. The dive's scatter changes what a tap hits, never the rolls.
- **"Predator" means two things:** a surface feature's predator prefers predator bait (D102); the tank and hiding use
  the fish's `predator` mark (D152).
- **`timingFrom` in `src/engine/game.js` must carry `fightMs`:** it isn't a game value, and without it a manoeuvre
  never runs out (D141).
- **The map (D161) is the `map` pane drawn over the whole screen by `src/ui/map.js`,** not in the pane box. Its picture
  is baked from the owner's photo and drawing (`docs/design/map/`, local only) into `src/generated/map-paper.js`; a
  spot's `map` (a town's, for the whole town) is its place in that picture's 320 pixels, and a spot without one can't be
  gone to from the map (a test wants every spot placed). `mapMarks` (`src/engine/knowledge.js`) lists them; the button shows from two marks on. A press
  goes to the nearest mark in reach, since the circles are small on a phone.
- **`src/main.js`: `castInProgress()` is not `lineOut()`.** Saves are held back only while a cast is in progress;
  equipment can't change then, nor in the pause after a missed splash (`lineOut()`).
